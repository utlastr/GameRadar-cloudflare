# 热度雷达（Python）

在自己电脑上定时抓取各平台热度，找出"一个地方火了、另一个地方还没人做"的 Fast Follow 机会。
只用 Python 自带的库，**不需要 pip 安装任何东西**（需要 Python 3.8 以上）。



## 游戏身份规则：一个游戏 = 一份档案（v73，`radar/archive.py`，全部自动判断）

每个游戏一份档案。档案的成员是"平台:编号"（`steam:123`、`taptap:456`、`wxmini:789`、`huya:分区名`……）和 B站 话题 `btopic:<名字>`。
所有页面、打分、提醒、B站 数据都按档案算。**没有待确认，不需要人判。**

- **天然同一个**：同一个平台编号（TapTap 榜单和 TapTap制造共用 TapTap ID，App Store 中美区共用 App Store ID）。
- **确定的连接**：商店页里写着另一个商店的地址（Steam / TapTap / App Store 链接）；成功案例配置里写的别名。
- **其余全部自动判断：Fellegi–Sunter 概率记录链接**（美国人口普查局、英国司法部开源的 Splink 用的方法）。
  - 候选：名字归一化后完全一样（同名的超过 `ARCHIVE_BLOCK_MAX` 款算泛名，不当候选），或 B站 视频简介里挂着某个 Steam 链接。
  - 每对比较：开发商 / 发行商（一致 / 对不上）、上线日期差（≤7 天 / ≤30 天 / ≤1 年 / >1 年）、名字撞了几款、名字长短、两边平台类型、含不含大作名、共现视频数。没有的项不算（既不加分也不减分）。
  - 权重从数据里算：u（不是同一个时这一项长什么样）的开发商和日期从 `ARCHIVE_U_SAMPLE` 对随机配对里估；其余参数用 EM 从候选对本身估。
  - 每对得到"是同一个的概率"，**大于 0.5 就连**（最大后验判定）。
  - 同名撞车：同一个平台上有两款都可能，取概率高的那一款；两款概率一样（分不出来）就都不连。
  - 超级产品（名字里带大作名）、开发商对不上：作为比较项进模型，数据决定它们降多少，不再一刀切。
- **硬约束**：一份档案里每个平台只能有一个编号（B站 话题除外，一个游戏可以有好几个叫法）。
- **纠错**：详情抽屉 → 游戏档案 → "连错了，拆出"。等于把它和档案里其他成员都记成"不是"，整份档案检查，不会经第三方再连回来。
- 运行情况页底部「游戏档案：自动判断」：连了多少、各种没连的原因、模型估的同一个比例、5 个样本游戏（竞拍之王 / 铸剑大师 / 翡翠精英模拟器 / ForgeTax / 影之刃零）现在各对上哪些档案；`ARCHIVE_GOLD` 填了标准答案就显示对 / 漏 / 多。
- B站 话题至少 `BILI_TOPIC_MIN_UP` 个不同 UP 主在做才登记。旧的 `links` 表永远不再使用。
- 成功案例的 `hit:jade` 这类编号只是案例内部编号，它的标签 / 标题短语就是档案里的 B站 话题成员。

## 发现链路更新（2026-10-19）

- Steam：最近 30 天发行扫描的 App ID 进入实时游戏池；独立扫描保存翻页进度。新发现游戏有单独的指标采样任务，不必等待完整 Steam 抓取。各平台 → Steam → 近期发行追踪可检查是否已采样。每轮导入和采样有数量上限，不代表已完成全量覆盖。
- B站：按 BV 号保存视频及每次真实播放量；游戏排行、热门、可配置关键词搜索和已发现 BV 的持续采样独立运行。默认每 30 分钟一次，不受 TapTap 长任务阻塞。各平台 → B站视频 → 传播线索列出证据；“必看”只展示游戏，不展示视频列表。搜索集合的作者数量不代表同一款游戏的作者数量。
- 关键词和指定视频分别配置 `BVIDEO_SEARCH_TERMS`、`BVIDEO_WATCH_IDS`。视频标题从不作为游戏身份；仅简介明确给出的 Steam 商店 URL 可记录对应 ID，其他情况显示待核对。首个播放快照不计算增长，至少间隔半小时的两个快照才计算实际增量。
- 初始关注阈值：近 14 天发布且累计播放至少 5 万，或观测到每小时新增至少 1 万播放。它们是研究线索，不是收益判断。采集失败、部分覆盖和过期分别显示。原来的名称聚合视频历史不迁移为 BV 采样，也不补造过去播放量。
- 游戏累计指标有至少 1 小时、至多 12 小时的实际采样间隔时，可以生成近期发行游戏的短期信号，不以等满三天为前提；短期信号注明实际时间窗口。
- “快速通道”现改名“增长异常”；超过 6 小时的旧采样不能触发这个标签。TapTap 页面显示官方热度，不把它称为实际下载量。
- `TAPTAP_WATCH_IDS` 是固定 ID 追踪清单；重点采样线程独立于 Steam、标签页长任务，按 `TAPTAP_PRIORITY_MINUTES` 重试。运行情况显示每个 ID 的采样结果和失败原因。热度、关注数只从当前 ID 的对象解析，网页验证页或其他游戏的数据不会覆盖旧值。

## 怎么用

**双击 `GameRadar.pyw` 就行。**

- 不会出现黑色窗口，右下角托盘会出现一个蓝色圆形图标（可能藏在任务栏的"^"小箭头里）


- **左键单击图标**：打开面板（浏览器打开 http://127.0.0.1:8765 ，只在本机能打开）
- **右键图标**：打开面板 / 查看运行情况 / 立即刷新数据 / 打开日志文件 / 开机自动启动（默认已勾选）/ 检查更新 / 退出
- **想知道程序在干什么**：面板右上角实时显示当前任务；左边“运行情况”页有进度和实时日志（相当于黑色命令行窗口）；鼠标停在托盘图标上也能看到
- 第一次启动会自动设置开机自启，以后开机就在后台运行；不想要的话右键取消勾选
- 已经在运行时再双击，会直接打开面板，不会重复启动
- 发现机会时右下角弹通知，每天最多 5 条
- 运行日志：`radar_data/radar.log`；启动失败会弹窗，错误保存在 `radar_data/error.log`
- "比昨天涨了多少"要跑满 24 小时后才有

需要 Python 3.8 以上（python.org 安装时勾选 "Add python.exe to PATH"）。不需要 pip 安装任何东西。

调试用（会显示黑色窗口）：`python run_radar.py --once` 只抓一次并显示每个平台的结果。

## 面板有哪些页

v54 起菜单最下面多一个“地图”（单独的 `/map` 页，见下面「地图」）。

v24 起左边只有 3 页，按“要做什么”分，不按平台分；所有平台平等，没有主平台。页内用分栏切换，不再加左边的栏：
- **必看**：只有新游戏（`analyze._new_games`：上线不超过 `NEW_MAX_DAYS` 天，老牌大游戏、判断不了上线时间的不进），按 `radar/heat.py` 的异常值排名。视频互动和已采集的累计评论、下载/官方热度、预约、关注、访问先换成每日新增；最近三天按 50%/30%/20% 平滑，趋势 `(最近三天日均 - 此前七天日均) / 两者之和` 最多调整基础量 ±20%，缺基线不调整。各平台各指标分别归一化，同平台多指标取平均后合并平台分数，不把评论条数与下载次数直接相加。只有名次或在线人数的不套累计差分；没有有效增量的游戏仍保留参考项。两种排名（降分开 / 关）各取前 400 做卡片，总数照实写
- **纯趋势**：必看默认视图，独立于综合分。对每个游戏取最强的有效指标，按最近三天日均量 / 此前七天日均量排序，累计指标比较新增、在线等即时值比较日均水平；基数、规模、标签降权和平台数量不参与此排序，同倍率按档案编号稳定排序。原始评论总数、官方热度和在线人数单独展示，不换算成人数。零基线启动单列，不生成无穷倍率；基线不足不冒充零增长。综合、原始综合和纯趋势各保留前 400 的并集，避免综合分截断趋势候选。最终如何结合规模暂不添加新权重，原综合模式保留。
- **各平台**（v31）：左边平台目录按综合应用商店 / 小游戏平台 / 直播平台 / 视频平台分组（`index.html` 的 `PLAT_DIR`），没接上的平台也列着（`todo` 名字必须和 `config.PLATFORM_TODO` 第一列完全一样），点开显示原因和要提供什么；手机上目录换成下拉框。每个已接平台同样三栏：新冒头 / 涨幅榜 / 全部数字。TapTap、TapTap 制造多一栏“每周 / 每月新增”（原来的大盘，制造里再切创意工坊），因为只有它们的热度是累计下载，能算每期新增；Steam 在线人数、直播热度是当前值，算法不一样，还没做
- **运行情况**：实时日志、AI 用量、抓取记录图表
- 旧书签 `#maker`、`#tapboard` 自动跳到各平台对应的栏

虎牙、斗鱼（v21 起）看两样，不再从标题括号里拆词（括号里大多是主播标签、比赛名，如 CSTG）：
- **分区**：开始运行时就有 15 个以上主播的老分区（英雄联盟、和平精英……）不显示。之后新开的分区（竞拍之王在虎牙就有单独分区）按几个主播在播直接给热度，不用等 24 小时；开始运行时就有但很小的分区，涨了才显示，标"老分区"往后排
- **分区主播数 / 热度**：大小主播全算在内，分区涨了就有热度，不看是不是大主播
- **没有自己分区的游戏**：在单机热游、主机游戏这类大杂烩分区里，数有几个主播（大小都算）的标题里写了 Steam、TapTap、TapTap制造、Roblox 上已经抓到的游戏名（来源 `huya_t`、`douyu_t`），和那个游戏合并成一张卡。只用已知游戏名去找，不再瞎拆括号；带英雄联盟这类大游戏名的不找
- **大主播**（补充，不是主要依据）：最近 30 天进过本平台游戏区热度前 150 的主播（名单记 30 天，换去播小游戏热度掉了也认得）。（v74 起页面上不再列"大主播在播"）他们在播的分区、或在大杂烩分区标题里写了某个已发现游戏的名字，这个游戏国内热度至少算 0.6，卡片标"大主播在播"
- 想关掉某个平台：`settings.json` 写 `"SOURCES_ENABLED": {"douyu": false}`

## 地图（v54，`radar/worldmap.py`、`radar/web/map.html`）

左边菜单“地图”打开 `/map`，单独一页（地球 / 平面切换，底图和人口点沿用「人口地球」）。
- **数据**：后台线程每小时醒一次，当天（UTC）没抓的国家就抓苹果旧版 iTunes RSS 游戏榜（`genre=6014`，畅销榜 + 免费榜各前 100，约 170 个国家和地区，间隔 1.5 秒，失败的当天最多重试 2 次）。存 `world_charts`（日期、国家、榜、名次、应用编号），游戏资料存 `world_apps`，类型用 lookup 接口查。连续 4 次 403 就停一小时（状态里写“苹果拒绝访问”）。`settings.json` 写 `"SOURCES_ENABLED": {"world": false}` 关掉
- **相似度**：名次 → 权重 r^-0.75，国家内归一化成份额（和市场大小无关）；每款游戏、每个发行商乘 log(国家数 / 上榜国家数)，全球爆款接近 0；类型份额减全球平均。相似度 = 0.5 游戏 + 0.25 发行商 + 0.25 类型（余弦）。发行商这项是为了同一游戏各国编号不同（Garena 等）
- **两条线（v56）**：
  - 噪声地板：每个地方自己和自己比的相似度。当天榜单有放回重抽两份比（12 次平均），有前一天数据时再比今天和前一天，取低的。两地相似度 ≥ 两者地板中低的那个 = 盲测分不出来（以后拆州 / 省时，子区域之间分不出来就不拆）
  - 背景水平（成圈线）：所有两两相似度的中位数 + 3 × 稳健标准差（MAD × 1.4826），且不高于地板中位数的 0.9
- **玩家圈**：平均联结聚类，两组之间平均相似度低于成圈线就停，圈数由数据决定；只有自己的标“（独立）”。名字 = 最核心的两个成员（“台湾·香港圈”），不用类型、语言、地理区命名；每次重算按成员重合度（Jaccard ≥ 0.5）沿用上次的编号和名字。不要求地理相连。徽章上的“偏爱”列多项类型（倍数 ≥ 1.1 的前 4 个），不只一个
- **画法规则**：颜色只表示人均收入（世界银行人均国民收入，现价美元，对数刻度，30 天更新一次；没有的用 Natural Earth 自带的人均 GDP）。玩家圈只用徽章，不用颜色。点一个国家：其他国家按和它的相似度变亮 / 变暗；右边列出它比全球平均更偏爱的游戏（×倍数）、类型、发行商、最像的地方
- **悬停徽章**（v55）：鼠标停在哪里，弹出它所属玩家圈的徽章（盾形，中间是圈里最具代表性的游戏图标 + 编号）、圈名、成员数、代表游戏；和第二个圈也很接近（≥ 本圈的 85%）时写“也接近 Gx”。没选中国家时，悬停会把同圈的地方点亮。代表游戏 = 圈内成员偏爱度（游戏份额 × 稀有度）平均最高的；`aff` = 和每个圈成员的平均相似度，前 3 个
- **地名（v57）**：只显示“当地语言 · 英文”，由浏览器 `Intl.DisplayNames` 生成，语言表 `LANG` 在 map.html 里；圈名在前端用核心成员（结果里的 `core`）的英文名拼，服务端的中文 `name` 不显示
- **太阳系（v58）**：太阳、火星、比邻星和地球在同一个三维场景里，没有切换按钮。地球半径 = globe 半径（100），其他按真实半径和真实距离（按当前日期算的大致位置：太阳 1 AU、火星椭圆轨道近似、比邻星 4.25 光年）。远处天体用“等角缩放替身”：距离超过 `LIM` 时把网格挪到相机附近、按比例缩小，看上去大小不变，避免浮点精度和深度问题；相机 near/far 每帧按离最近天体表面的距离调整；星空球跟着相机走、不写深度。天体贴图复用地球的球体网格（`/map/a/sun`、`mars`、`mars-bump`，来自 threex.planets；比邻星 = 太阳贴图染红）。看起来小于 24 像素的天体显示英文名标签，点标签或点天体本身会“对数距离”飞过去；轨道控制的中心、缩放和旋转速度按当前天体调整，可以一路缩放出去。悬停太阳 / 火星 / 比邻星显示人均收入 $0k、人口 0，图例最左端也标了
- **v70**（合并）：撤掉 Radar / Globe 拆分，回到一个程序、一个版本号、一个更新（地图代码回到 `radar/worldmap.py`、`radar/incgrid.py`、`radar/regions.py`、`radar/web/map.html`、`radar/web/map/`，接口回到 `/api/world`、`/api/incgrid`、`/api/regions`）。时间速度固定 ×360，去掉切换按钮
- **v69**：省 / 州级口味。
  - 边界：`radar/regions.py` 后台下载 Natural Earth 10m 一级行政区（约 40MB），只留目标市场，简化后存 `radar_data/regions.json`，每个人口格子归到覆盖最多的行政区，算人口。失败半小时后再试
  - 目标市场：`settings.json` 的 `"MARKETS"`（不填用 `regions.DEF_MARKETS`：ru cn us jp kr tw de fr gb br mx id th vn ph my sa ae tr ca au）。中国大陆要 `"BAIDU_COOKIE"`（登录 index.baidu.com 复制含 BDUSS 的 Cookie），不填不拆。这两项由 regions 直接读 settings.json
  - 词：每个市场本国榜单份额前 25 款游戏 + Steam / PlayStation / Xbox / Switch + 娱乐（`ENT`：抖音/TikTok、快手/Kwai、B站、小红书、微博、虎牙、斗鱼、YouTube、Instagram、Twitch、Netflix、动漫、足球、篮球/NBA、电竞、短剧、网文；中国大陆用中文词）。Google Trends 各省 / 州 12 个月热度（游戏优先用“主题”），中国大陆用百度指数 30 天。存 `region_trends`，14 天刷新，每轮最多 60 个词、间隔 8–14 秒，连续 3 次失败标“被拒”一小时。新数据到了触发重算
  - 偏好倍数 = 该地热度 ÷ 全国人口加权平均（0.2–5）；游戏词覆盖不到 40% 的地区不用，至少 2 个地区才拆
  - 一层玩家圈（`worldmap._place_layer`）：地区份额 = 国家份额 × 偏好倍数再归一化。相似度统一换算成“超出各自门槛多少”：跨国两地 (S − 背景水平)/(1 − 背景水平)；同国两省 (余弦 − 2/√维数)/(1 − 2/√维数)，余弦用游戏 + 平台 + 娱乐的对数倍数。门槛 0 完全联结，圈里任意两地都过各自的门槛。圈带 `ent`（成员几何平均 ≥ 1.15 的前 3 项）

## 打分

原则：宁可多看，不能漏。**只有热度决定看不看得到**，其他判断只改排序或加标签。只有两种情况收起来：你标了"不做"；你点了"先不看"（热度涨到当时的 1.5 倍自动回来）。缺数据不扣分。

分数 = 100 × 热度 × (0.25 + 0.75 × 能不能跟) × 标签折扣
- 热度：老游戏和昨天同一时刻比、和同平台同量级比（扣除大盘）、累计异常分；**上线 14 天内的新游戏**另按"上线以来平均每天涨多少"（Steam 评论数、TapTap 热度、Roblox 访问）和同平台新游戏比，抓到一次就能算，两者取高
- 能不能跟：你打的星 > AI 读评论 > 标签（没标签按中等算）
- 上线时间权重（v23）：每个被发现的游戏都先查上线时间（已抓到的 Steam/TapTap/Roblox → App Store 中国区搜索 → Steam 商店搜索，`radar/launch.py`，按名字缓存 30 天）。30 天内 ×1、90 天 ×0.7、180 天 ×0.4、一年 ×0.15、超过一年 0 分，放进"必看 → 老游戏"。查不到不扣分，标"没查到上线时间"；查不到但开始运行时就很大的直播分区按老游戏算
- 也算老游戏（0 分）：程序开始运行第一天就有的直播分区（查到一年内上线的除外）；名字里带 `KW_BIG_GAMES` 里老牌大游戏名的（绝区零、和平精英模拟器、火影忍者手游……），不管 Steam 上线日期
- 大厂新游戏 ×0.4、重度大作 ×0.5：降权不排除
- 打星 = 你判断能不能跟，代替 AI/标签：1 星 ×0.33 … 5 星 ×1；3 星以上还取消上面所有折扣。打星、不做、无关点完 2 秒内用已有数据重算（`server.reanalyze_soon`）
- 流量太小的不显示：各平台最低门槛见 `config.ANALYZE`、`LAUNCH_METRIC`
- 只加标签不改分：打折中、名字带更新/活动、能和陌生人对战 / 朋友联机型、海外火中国没热度、目标平台搜到同名游戏（按名字搜，不进分数）
- Steam 上线 60 天内的游戏掉出榜单后继续跟踪（在线人数、评论数）；Roblox 用 games 接口拿原始英文名、创建时间、累计访问

## TapTap 怎么抓（v18 起，照参考网站 as167888 的爬虫）

不用任何 TapTap 接口（`webapiv2` 接口 2026-10 起返回 400），只看网页，做法照 as167888/taptap-maker-tracker 和 as167888/TapTrack：

- 掉出标签页的老游戏：上线 14 天内的 3 小时补一次，其他 20 小时一次，每轮最多 250 个（这是雷达自己的调度，参考网站每轮全量重抓）
- 创意工坊：TapTap 没有这个标签页（打开 404），参考网站没公开做法，v18 起不再发现新的创意工坊游戏，以前发现的照常补详情
- TapTap 榜单（`taptap`，每 6 小时）：翻热门 15 页、热玩 15 页、新品 10 页、独家 10 页、17 个分类榜各 5 页（`div.list-item`），再逐个打开详情。没有预约榜（参考网站没有），所以 `reserves` 不再有新数据
- 抓 TapTap 时每分钟检查一次直播是否到点，到点先插一轮虎牙斗鱼（`collect._between`）
- 热度到 100 才开始记每小时数据，不到的只记名字（供给检查用）；`extra.kind` = maker / workshop
